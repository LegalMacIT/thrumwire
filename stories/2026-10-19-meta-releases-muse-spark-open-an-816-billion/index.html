Meta releases Muse Spark Open, an 816-billion-parameter open-weight model built to run on Macs

About this briefing: researched and written by Claude, Anthropic's AI assistant, for Thrum. Selected for publication by Hector A. Cruz. Facts are from the linked source. About Thrum

Meta bills the model as the most capable open-weight system in the US, and it is designed to run on desktop Mac hardware, which is unusual for a model of this size.

  • Meta's Muse Spark Open has 816 billion parameters and a 1 million token context window.
  • Meta's own evaluation results, released on 15 October, claim it outperforms other popular open-weight models. These figures had not been independently verified in the source reviewed.
  • The model was designed to work with Macs, though the article notes that running it takes a lot of memory.
  • Meta paired it with Muse Code, its AI coding terminal. In one agentic demonstration the model made bug fixes, added features and produced a full build for a Mastodon client.
  • The model is available now through several API platforms.

Meta describes Muse Spark Open as the most capable open-weight model in the United States. It has 816 billion parameters and a 1 million token context window. Meta supports the claim with its own evaluation results, which had not been independently replicated in the source reviewed. The notable design choice is support for Macs, which moves a frontier-scale open model closer to local, desktop use.

The agentic coding demonstration, in which the model fixed bugs, added features and completed a full build for a Mastodon client, shows the model is aimed at multi-step work and not only chat. Memory requirements remain a practical limit, and the source does not give hardware specifications or licence terms.

The release matters for professional-services buyers because open weights make it possible to run a strong model inside a firm's own environment. That addresses a common objection to cloud AI: client data leaving the firm's control. It also adds to the number of credible alternatives to closed vendors, which strengthens buyers' position in pricing and contract negotiations.

For legal-technology advisers: Clients that have ruled out hosted models on confidentiality grounds may now have an on-premises option. Advisers should ask for the licence terms, which were not in the source reviewed. They should also request the hardware requirements and a test of the model on the client's own document and drafting tasks, and should not rely on Meta's self-reported benchmarks. Advisers should also set out the security, patching and monitoring work that self-hosting adds.

For lawyers deploying AI: Local deployment can reduce confidentiality exposure, but it does not remove the duty to supervise and verify outputs. Any pilot should use non-client matter data first, keep a record of the model version used, and require human review of anything the model produces. Lawyers should also confirm that the API platforms offering the model do not retain or train on client inputs.
